# PocketContext Atlas 0.25.0

PocketContext is now the family name; this knowledge base is **PocketContext Atlas**,
with its own repository and executable `pocketcontext-atlas`. The shared server moved
to the `pocketcontext-core` library. No data format, database, backup or hosted
container contract changed.

## What changes for you

- **New repository and executable.** Releases come from
  `pocketcontext-labs/pocketcontext-atlas`; the executable is `pocketcontext-atlas`
  (`--version` prints `pocketcontext-atlas VERSION`). Earlier releases and their
  URLs stay available at `pocketcontext-labs/pocketcontext`.
- **Own skill and registry.** The skill directory is `pocketcontext-atlas`, with its
  own markers, and the profile registry is `<config>/pocketcontext-atlas/profiles.json`.
  The earlier shared skill and `<config>/pocketcontext/` registry are not modified.
- **New image.** Hosted containers use `ghcr.io/pocketcontext-labs/pocketcontext-atlas`.
  The hosted volume, `/storage`, `pocketcontext-container`, the upgrade receipt, backup
  format, `/up` and all `POCKETCONTEXT_*` variables are unchanged. See
  [hosting](../hosting.md).
- **Installers.** They accept the old `pocketcontext` executable as the replacement
  source (`POCKETCONTEXT_REPLACE_VERSION=<its version>`) and leave it in place for the
  runbook to move into the backup. A folder with a database and neither executable
  is refused. The old executable is the replacement source only; installation never
  happens over it.
- **Instance check.** A 0.25 client recognizes a running 0.24.x server so it can be
  diagnosed and stopped, but never adopts it. Upgrade the server and its paired
  clients together.

Upgrading: see the [runbook](../upgrades.md). Everything else: no behaviour change;
the public route allowlist is pinned by a golden table.

## New

`upgrade-check --db DB [--from VERSION] [--inventory]` is a read-only local
diagnostic for the steps in the runbook.
